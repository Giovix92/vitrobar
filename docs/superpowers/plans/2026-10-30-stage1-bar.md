# Vitrobar Stage 1 — The Bar — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A usable, glass taskbar replacement on every monitor — Start button, pinned apps, grouped open windows with live thumbnails, tray icons with overflow, clock — that hides the stock taskbar while running and always gives it back.

**Architecture:** A Cargo workspace. `vitro-core` holds every decision that can be made without Windows (settings, layout geometry, window grouping, tray protocol parsing, style tokens) and is unit-tested with TDD. `vitro-win` wraps Win32/Shell (window tracking, icons, tray hosting, stock-taskbar control). `vitro-render` draws with **Windows.UI.Composition** on a D3D11 device created on the minimum-power adapter: the compositor is retained-mode, so between animations Vitrobar submits nothing and uses no CPU/GPU. The `vitrobar` binary wires them together on one UI thread and also runs as its own watchdog.

**Tech Stack:** Rust stable (MSVC), `windows` crate (latest release at time of execution, exact version pinned in `Cargo.lock`), `serde` + `toml`, `embed-resource` for the manifest. No webview, no .NET.

**Spec:** `docs/superpowers/specs/2026-10-30-vitrobar-design.md` — read it first. This plan implements **§9 stage 1** only.

**Builder's call recorded here:** the spec says "Direct3D 11 + DirectComposition". This plan uses Windows.UI.Composition, the WinRT layer over the same system compositor, because it provides `HostBackdropBrush` (a real blur of what is behind a window, clipped to any shape — needed for pill/island corners) and compositor-driven animations. Raw DirectComposition is still available for later stages if needed.

## Stage 1 scope

In: three shapes, materials frosted/smoked/solid black/solid white, four hover effects, pins, grouped windows, click behaviour, thumbnails, tray + overflow, clock, multi-monitor, per-virtual-desktop filtering, DPI, stock taskbar hide/restore, work-area reservation, fullscreen hiding, watchdog, start-with-Windows, first-run pin import, right-click menus (native popup menus for now), perf CI.

Out (later stage plans): Vitrobar Start menu and Windows-key hook (stage 2; Start button opens the stock Start menu for now), glass settings window (stage 2; stage 1 changes settings through the bar's right-click menu), quick panels / notifications / system tray icons such as volume and network (stage 3; a "quick settings" button and the clock open the stock Windows panels for now), liquid glass (stage 4), widgets (stage 5), progress/badges, jump lists, drag & drop, installer/signing/winget.

## Global Constraints

- Windows 11 only; targets `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`.
- Budgets: RAM < 40 MB total of all Vitrobar processes, bar idle, panels closed; idle CPU 0%; idle GPU 0%; bar on screen < 300 ms; download < 5 MB.
- Redraw only on change; animations 150–250 ms; respect "Animation effects: off" (no animation, final state immediately).
- D3D device on `DXGI_GPU_PREFERENCE_MINIMUM_POWER`; never the discrete GPU.
- Never modify Windows permanently; never inject into other processes; undocumented interfaces only read-only/normal call path, guarded, fail by hiding the feature.
- No telemetry, no network in stage 1.
- Runs unelevated (`asInvoker`), Per-Monitor-V2 DPI aware.
- UI strings in English and Italian through `vitro_core::i18n`.
- License GPL-3.0; every commit authored as `Giovix92 <ggualtierone@gmail.com>`.

## Review Focus

1. **Explorer restarts or crashes while Vitrobar runs** → within 2 s the stock taskbar is hidden again and tray icons repopulate (Task 11, Task 12).
2. **Vitrobar is killed hard (`taskkill /F`, crash, "End process tree")** → the stock taskbar, its auto-hide setting and the work area come back; nothing stays changed after the next sign-in (Task 11, Task 15).
3. **An app is hung ("Not Responding")** → the bar stays responsive; every cross-process call uses `SendMessageTimeoutW` ≤ 100 ms with `SMTO_ABORTIFHUNG` (Task 7, Task 8).
4. **Too many apps for the bar, or a narrow / portrait monitor** → no overlapping items, nothing outside the glass, overflow goes into a "more" button (Task 2).
5. **Malformed/truncated tray data, 32-bit senders, and tray icons whose owner process died** → never crashes; dead icons are removed (Task 4, Task 12).

```rust
    pub start: Rect, pub apps: Vec<Rect>, pub more: Option<Rect>,
```

Pinned values:
- `metrics`: Small `{40,20,32}`, Medium `{48,24,40}`, Large `{56,28,48}`.
- Floating margin from screen edge and between islands: `8`. Inner padding: `6`. Gap between Start, apps, tray groups inside one surface: `8`. Chevron and quick button are one `slot` wide each; clock is `clock_w`.
- Pill/Islands: `radius = bar_h / 2`; Full: `radius = 0`, spans the monitor width, touches the edge.
- Pill: one surface, centred horizontally, width = content width. Islands: start island at left margin, apps island centred, tray island at right margin. Full: Start at left, apps centred on the monitor, tray/clock right-aligned.
- Position Bottom: surface bottom = monitor bottom − margin (floating) or monitor bottom (Full). Top mirrors it.
- `reserved`: Full → `bar_h`; floating with `reserve_floating` → `bar_h + 2*margin`; else `0`.
- `show_desktop`: 6 DIPs wide, full bar height, at the right edge of the rightmost surface (inside it).
- Not enough room: app slots shrink, but to no less than `icon + 4`. If they still don't fit, the last visible slot becomes `more` and the remaining apps are not laid out (`apps.len() < app_count`). Islands centred island must not overlap the side islands (min gap = margin).

```rust
    pub title: String, pub visible: bool, pub tool_window: bool, pub app_window: bool, pub has_owner: bool,

    pub minimized: bool, pub flashing: bool }

pub fn group_key(w: &WindowInfo) -> GroupKey
pub struct AppGroup { pub key: GroupKey, pub pin: Option<usize>, pub windows: Vec<Hwnd>, pub active: bool, pub attention: bool }

pub fn click_action(g: &AppGroup, foreground: Option<Hwnd>) -> ClickAction
```
Rules:
- `is_taskbar_window` = `visible && !cloaked_by_app && (app_window || (!tool_window && !has_owner))`. (`cloaked_by_app` excludes UWP frames that are hidden by their app; windows on other virtual desktops are handled by `on_current_desktop`, not here.)
- `build_groups`: consider only taskbar windows with `monitor == monitor && on_current_desktop`. Pins first, in pin order, each as a group (with matching windows, possibly none). Pin matches a window when the pin's `aumid` equals the window's aumid, or pin `path` equals window `exe_path` case-insensitively. Then unpinned groups ordered by their lowest `seq`. Windows within a group ordered by `seq`. `active` if any window is `foreground`. `attention` if any `flashing`.
- `click_action`: no windows → `Launch(pin)`; one window → `Minimize` if it is foreground, else `Activate`; several → `ShowThumbnails`.

### Task 4: Tray protocol and tray model

**Files:** Create `crates/core/src/tray_wire.rs`, `crates/core/src/tray_model.rs`.

**Interfaces:**
- Produces:
```rust
// tray_wire
pub const TRAY_COPYDATA_ID: usize = 1;          // COPYDATASTRUCT.dwData for Shell_NotifyIcon
pub const TRAY_SIGNATURE: u32 = 0x3475_3423;
pub enum TrayOp { Add, Modify, Delete, SetFocus, SetVersion }   // NIM_ADD=0 .. NIM_SETVERSION=4
pub struct TrayIconId { pub hwnd: u32, pub uid: u32, pub guid: Option<[u8; 16]> }
pub struct TrayMessage { pub op: TrayOp, pub id: TrayIconId, pub callback_msg: Option<u32>, pub hicon: Option<u32>,
    pub tip: Option<String>, pub hidden: Option<bool>, pub version: Option<u32> }
pub enum TrayParseError { TooShort, BadSignature, UnknownOp(u32) }
pub fn parse_tray_copydata(bytes: &[u8]) -> Result<TrayMessage, TrayParseError>
// tray_model
pub struct TrayIcon { pub id: TrayIconId, pub callback_msg: u32, pub hicon: u32, pub tip: String, pub hidden: bool, pub version: u32 }
pub struct TrayModel { /* icons in insertion order */ }
impl TrayModel { pub fn new() -> Self; pub fn apply(&mut self, m: TrayMessage) -> bool; pub fn icons(&self) -> &[TrayIcon];
    pub fn remove_owner(&mut self, hwnd: u32) -> usize }
```
Wire format (always 32-bit handle fields, whatever the sender's bitness), little-endian, offsets from start of payload: `0 signature u32`, `4 message u32`, then NOTIFYICONDATAW32: `8 cbSize`, `12 hWnd u32`, `16 uID`, `20 uFlags`, `24 uCallbackMessage`, `28 hIcon u32`, `32 szTip [u16;128]`, `288 dwState`, `292 dwStateMask`, `296 szInfo [u16;256]`, `808 uVersion`, `812 szInfoTitle [u16;64]`, `940 dwInfoFlags`, `944 guidItem [u8;16]`, `960 hBalloonIcon`. Fields are read only when present in the buffer and indicated by `uFlags` (`NIF_MESSAGE 0x1`, `NIF_ICON 0x2`, `NIF_TIP 0x4`, `NIF_STATE 0x8`, `NIF_GUID 0x20`); `hidden` only when `dwStateMask & NIS_HIDDEN(0x1)`. Strings stop at first NUL. A buffer that ends before `hWnd`+`uID` is `TooShort`; shorter optional fields are treated as absent (older `cbSize`). Verify these offsets against ManagedShell's `SHELLTRAYDATA`/`NOTIFYICONDATA` definitions before trusting them.

Model rules (match Explorer): identity = `guid` if present else `(hwnd, uid)`. `Add` of an existing id → `false`, no change. `Modify`/`Delete`/`SetVersion` of unknown id → `false`. `Modify` updates only provided fields. `SetFocus` → `true`, no change.

### Task 15: Watchdog, single instance, start with Windows

**Files:** Create `crates/core/src/restart.rs`, `app/vitrobar/src/watchdog.rs`, `crates/win/src/autostart.rs`; modify `app/vitrobar/src/main.rs`.

**Interfaces:**
- Produces:
```rust
// core::restart
pub enum Decision { Restart, GiveUp }
pub struct RestartPolicy { /* timestamps of recent restarts */ }
impl RestartPolicy { pub fn new() -> Self; pub fn on_crash(&mut self, now_ms: u64) -> Decision } // GiveUp on the 4th crash within 60_000 ms
// win::autostart
pub fn set_autostart(enabled: bool) -> Result<()>   // HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Vitrobar = "\"<exe>\""
```
Process model: `vitrobar.exe` (no args) = watchdog: takes named mutex `Local\Vitrobar.Watchdog` (if taken → exit 0; second launch does nothing), spawns `vitrobar.exe --bar`, waits on the process handle. Exit code 0 → watchdog exits. Non-zero/crash → `restore_stock_taskbar` (Task 11) immediately, then `on_crash`: Restart → respawn; GiveUp → exit, leaving the stock taskbar restored. `--bar` takes mutex `Local\Vitrobar.Bar`, installs a panic hook that restores the stock taskbar and exits with code 101, and watches the watchdog's process handle (passed as `--parent <pid>`): if the watchdog dies, the bar spawns a new watchdog that adopts it (`vitrobar.exe --adopt <bar pid>`). `--restore` = call `restore_stock_taskbar` and exit (used by RunOnce). Watchdog has no window, no COM, no GPU: target < 2 MB private memory. Autostart applied from `Settings.start_with_windows` at startup and when toggled.

### Task 16: Performance check and release checklist

**Files:** Create `scripts/perf-check.ps1`; modify `.github/workflows/ci.yml`, `docs/release-checklist.md`.

**Interfaces:**
- Consumes: the built `target/release/vitrobar.exe`.

`perf-check.ps1 -Exe <path> [-Apps 10]`: starts Vitrobar, opens 10 windows (`notepad.exe` ×5, `explorer.exe` ×3, `mspaint.exe`, `calc.exe`), waits 10 s, then samples for 30 s: sum of `PrivateMemorySize64` of all `vitrobar` processes, and their total CPU time delta. Fails (exit 1) when memory ≥ 40 MB, CPU time delta > 50 ms over 30 s, or `vitrobar.exe` ≥ 5 MB. Prints a one-line JSON summary. Always restores (`vitrobar.exe --restore`) and closes what it opened. CI: new job after build runs it on `windows-latest` (software rendering; GPU checks are manual). `release-checklist.md` gains "Performance (manual, hybrid-GPU laptop)": startup < 300 ms measured with `Measure-Command` until the bar window exists (script `-MeasureStartup` switch polls `FindWindow` for the bar class every 5 ms); GPU idle 0% in Task Manager for 60 s with each material; discrete GPU stays in "low power/off" (NVIDIA/AMD control panel or `Get-Counter '\GPU Engine(*)\Utilization Percentage'` shows no engine on the dGPU LUID for vitrobar).
